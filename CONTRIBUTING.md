# 🤝 Guía de Contribución

¡Gracias por tu interés en contribuir a este workshop!

---

## 📝 Cómo Contribuir

### Reportar Problemas

1. **Busca primero** si el problema ya fue reportado
2. **Abre un Issue** con:
   - Título descriptivo
   - Pasos para reproducir
   - Comportamiento esperado vs actual
   - Capturas de pantalla si aplica
   - Versiones (VS Code, AL, BC)

### Sugerir Mejoras

1. **Abre un Issue** con el label `enhancement`
2. **Describe**:
   - Qué mejorarías
   - Por qué es útil
   - Cómo implementarías la mejora

### Contribuir Código

1. **Fork** el repositorio
2. **Crea una rama**: `git checkout -b feature/mi-mejora`
3. **Haz tus cambios**
4. **Commit**: `git commit -m "feat: descripción de cambios"`
5. **Push**: `git push origin feature/mi-mejora`
6. **Abre un Pull Request**

---

## 📋 Estándares de Código

### Markdown
- Usar encabezados jerárquicos (# → ## → ###)
- Incluir emojis para mejor legibilidad
- Tablas para datos estructurados
- Bloques de código con lenguaje especificado

### Código AL
- Seguir convenciones de nombres AL estándar
- Incluir comentarios en español
- Tests para cada funcionalidad
- Documentación de procedimientos

### Commits
Usar [Conventional Commits](https://www.conventionalcommits.org/):
- `feat:` Nueva funcionalidad
- `fix:` Corrección de bug
- `docs:` Cambios en documentación
- `refactor:` Refactorización
- `test:` Añadir/modificar tests

---

## 🔍 Proceso de Review

1. Al menos 1 reviewer debe aprobar
2. Tests deben pasar
3. Sin conflictos de merge
4. Documentación actualizada

---

## 📜 Código de Conducta

- Sé respetuoso y constructivo
- Acepta feedback con apertura
- Ayuda a otros contribuidores
- Mantén el foco en mejorar el workshop

---

## ❓ Preguntas

¿Dudas? Abre un Issue con el label `question`.
